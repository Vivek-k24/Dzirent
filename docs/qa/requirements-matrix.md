## 4. Defect Classification & Escalation Rules

Any discrepancy discovered during verification is documented in `docs/qa/` and triaged according to this severity taxonomy:

1. **Blocking (P0)**: Breaks core journey, causes crash/unhandled exception, compromises security/credentials, violates mode boundary (e.g. connected request falling back to mock), or fails CI gate. Must be resolved before milestone sign-off.
2. **Major (P1)**: Functional deviation from specification (e.g., incorrect count deduplication, focus trap failure, URL query desynchronization, stale edit concurrency failure). Assigned directly to domain owner (`apps/web` -> Codex; `services/api` -> Claude Code).
3. **Minor (P2)**: Cosmetic imperfection, minor spacing deviation, non-critical accessibility advisory (e.g. color contrast edge cases in secondary badges), or non-breaking console warnings. Logged in QA report for subsequent polish.

*Antigravity does not modify production code without explicit recorded ownership handoff. Defects are routed to the responsible agent.*
